## 1. Method

I implemented my own calibration-free PTQ in the spirit of AdaptQuant (per-tile format selection among MX formats), not a reproduction of the paper. Scope: weights and input activations of the 7 projections of every block (252 Linear layers), fake quantization in fp16 on the GPU. A tile is 32 consecutive elements along the reduction dimension with one shared power-of-two (E8M0) scale. Each tile chooses between MXFP4 (E2M1) and MXFP6 (E2M3). Per tile and per format two shared exponents (the standard one and one above it) are tried and the lower-MSE one is kept; this costs no extra bits. The format is chosen from the tile itself: if the relative MXFP4 error ||x - Q4(x)||^2/||x||^2 exceeds a threshold, the tile is stored in MXFP6. Weights are decided once; activations are decided on the fly for every token.

**Why it is calibration-free.** No dataset is used to fit anything. The two thresholds (weights, activations) are quantiles of the same statistic over unit-Gaussian tiles (seed 0, no model, no data; derive_thresholds.py), stored in thresholds.json; the official run only loads them. **Honest note:** the two fractions (45% for weights, 40% for activations) that define the quantiles were chosen by running a few settings and looking at the realised bit rate and PPL on WikiText-2, so they are hyper-parameters picked with feedback from the evaluation set (three settings tried, listed below), although they are not derived from any model's calibration data.

**Differences from AdaptQuant.** AdaptQuant derives its thresholds from a calibration pass on Llama-3.1-8B and also selects a per-tile offset; my thresholds come from a synthetic Gaussian, there is no offset, and only two formats are used.

## 2. Result

| Quantity | Value |
|---|---|
| Final PPL (WikiText-2 test) | 14.64  (base fp16: 13.64; AdaptQuant: 13.98) |
| Weight bits (exact) | 5.230  (47.4% of tiles MXFP6) |
| Activation bits (realised on the evaluation) | 5.342  (53.1% of tiles MXFP6) |
| Effective bit rate (W+A)/2 | 5.286 <= 5.3 |

**Bit-rate calculation.** A tile has 32 elements. MXFP4 = 4 x 32 + 8 (E8M0 scale) + 1 (format tag) = 137 bits = 4.281 bit/element; MXFP6 = 6 x 32 + 8 + 1 = 201 bits = 6.281 bit/element. Weight bits = 4.281 + 2 x 0.474 = 5.230. Activation bits are counted over every activation tile that enters a quantized Linear during the WikiText-2 test evaluation: 4.281 + 2 x 0.531 = 5.342. (5.230 + 5.342)/2 = 5.286. AdaptQuant's 5-byte metadata is not counted (as allowed by the TA); my own 1-bit tag is counted.

## 3. Observations and discussion

| Setting | W bits | A bits | Avg | PPL |
|---|---|---|---|---|
| all MXFP4 | 4.281 | 4.281 | 4.281 | 17.24 |
| all MXFP6 | 6.281 | 6.281 | 6.281 | 13.90 |
| Gaussian fractions w 0.50 / a 0.50 | 5.329 | 5.507 | 5.418 (over budget) | 14.57 |
| w 0.45 / a 0.40 (final) | 5.230 | 5.342 | 5.286 | 14.64 |
| w 0.35 / a 0.45 | 5.024 | 5.425 | 5.225 | 14.92 |

**Selection works.** Uniform MXFP4 gives PPL 17.24 and uniform MXFP6 13.90 (about the base model). Interpolating linearly in bits between them would give about 15.6 at 5.29 bits; the per-tile choice gives 14.64, so spending the MXFP6 budget on the tiles that MXFP4 represents worst is clearly better than a uniform split. **Activations are heavier-tailed than Gaussian.** With the same Gaussian quantile for both tensors, 61% of activation tiles (versus 52% of weight tiles) were promoted, which pushed the bit rate to 5.42; that is why the activation fraction had to be lowered. Realised activation bits depend on the input data, so the bit rate is a measurement on the evaluation text, not a guarantee. **Difficulties.** Getting the budget right without data: the threshold cannot be set from the real activation distribution (that would be calibration), so I set it conservatively from a synthetic one. **Possible reasons for the remaining degradation (not isolated by experiments).** MXFP4 tiles containing outliers, where a power-of-two scale wastes range, and the 48-53% of tiles that stay in MXFP4. Embeddings, lm_head and the attention score computation stay in fp16 and are not quantized. **Limitations and improvements.** No real low-precision kernel (fake quantization only); a third level (MXFP8) for the worst tiles, a smarter data-free statistic (e.g. crest factor), or non-power-of-two scales would likely lower PPL further at the same budget.
